# SUDS Format Reference

This document serves as a comprehensive technical reference for the Stanford University Drawing System (SUDS) file formats, combining knowledge from original documentation and modern parser implementations.

## 1. DRW File Format

The DRW file format stores logic drawings and uses 36-bit PDP-10 words, typically represented as 12-digit octal values.

### Header
* **Version**: Optional, if missing the file starts with a body name. (Version is often 24).
* **Nomenclature Type**: ASCIZ string
* **Board Type**: ASCIZ string (Usually set to 0 and ignored on input)

### Library References
* Repeated strings of type names actually used in the drawing, followed by a `0` word.
* Repeated pairs of library filespec (ASCIZ) and library BITS, followed by a `0` word.

### Body Definitions (TYPE Block)
Defines the component macros used in the drawing.
* **Name of Body Definition**: ASCIZ string
* **Bits**: `BITS,,UNUSED`
* **Loc Offset**: `X, Y` (Initial body location offset)
* **Loc Char Offset**: `X, Y` (`400000` if using default)
* **Pin List**: Ends with `400000`
  * Loc of pin (`X,Y`)
  * `BITS,,PINID` (PINID is generated by the program)
  * `PIN POS,,PIN NAME` (default)
* **Line Segments**: Points describing lines in the type, ending with `400000`. (Low order bit = 1 if invisible line to this point)
* **Properties**: Ends with `0`
  * ASCIZ `VALUE TEXT`
  * ASCIZ `PROPERTY NAME TEXT` (`0` if text only)
  * Text Size (`0` if not normally displayed)
  * Text Location
  * Constant Offset

### Body Placements (BODY Block)
Defines instances of components on the drawing.
* **Location**: Loc of body
* **Orientation**: Orientation + `400000` (if location follows)
* **Placement Details** (if indicated by orientation flag):
  * `CARD LOC (OPT),,BODY LOC`
  * `X, Y` constant offset of location
  * `X, Y` char offset of location
  * `BODY BITS,,BODY ID` (generated)
  * ASCIZ `NAME OF BODY DEFINITION`
* **Properties**: Ends with `0`
  * ASCIZ `VALUE TEXT` (for properties & text local to this occurrence)
  * ASCIZ `PROPERTY NAME TEXT` (`0` for text only)
  * Text Size
  * Text Location
  * Constant Offset

### Points (Vertices and Interconnections)
Ends with `400000`
* Loc of Point
* Point ID (generated for points, or `<PIN ID,,BODY ID>` for pins)
* ID of down (`0` if none)
* ID of up (`0` if none)
* ID of left (`0` if none)
* ID of right (`0` if none)
* `BITS,,PIN NAME`
* **Text / CPIN data** (if text size != 0):
  * Size of text
  * `X,Y` constant offset from point loc
  * ASCIZ `TEXT`
  * If CPIN on in bits:
    * `CARD LOC (OPT),,I/O PIN LOC`
    * `X,Y` constant offset

### Set Centers
Ends with `400000`
* Loc of set center
* Followed by a list of Body IDs (ending in 0)
* Followed by a list of Point IDs (ending in 0)

### Trailer
The end of the file contains strings for metadata:
* ASCIZ `STRING DRAWN BY`
* ASCIZ `STRING TITLE LINE 1`
* ASCIZ `STRING TITLE LINE 2`
* `CARD LOC FOR WHOLE DWG`
* ASCIZ `REVISION STRING`
* ASCIZ `MODULE STRING`
* ASCIZ `VARIABLE STRING`
* ASCIZ `PREFIX STRING`
* ASCIZ `PROJECT STRING`
* ASCIZ `PAGE STRING`
* ASCIZ `OF STRING`
* ASCIZ `DRAWING CODE`
* ASCIZ `SITE LINE 1 STRING`
* ASCIZ `SITE LINE 2 STRING`
* ASCIZ `NEXT HIGHER ASSEMBLY NUMBER STRING`
* ASCIZ `DRAWN BY FILESPEC` (if double quote `"` first character, treated as literal string)
* ASCIZ `CHECKED BY FILESPEC`
* ASCIZ `ENGINEERED BY FILESPEC`

### Extra Parts & Signals
* **Extra Parts Declaration**: Ends with `0`
  * ASCIZ `DESCRIPTION`
  * ASCIZ `PART NUMBER`
  * # of parts
  * Location
* **Signals**: Ends with `0`
  * ASCIZ `SIGNAL NAME`
  * ASCIZ `SIGNAL PROPERTY NAME`
  * ASCIZ `SIGNAL PROPERTY VALUE`
* **DIP Definitions**: ASCIZ `DIP DEFINITION FILESPEC`, ends with `0`
* **Wire Rule Check**: ASCIZ `WIRE RULE CHECK FILESPEC`, ends with `0`

## 2. WD File Format (Wirelist Drawing)

The WD format encapsulates a logical netlist directly derived from drawing structures. 
* **Header**: Version (WDVER), card loc (CRDLOC), date (DRWDAT), filename, titles, nomenclature, board type, drawing bounds.
* **Bodies**: `0`-terminated list.
  * ApproxLoc,,BID; BRSLOC; BodyBits,,0; TypeName; PackageName; Properties (name,,value pairs).
* **Signals/Wires**: `0`-terminated list ending with a null wire.
  * Signal names (0-terminated)
  * Pins: BID; PinID,,PinName; Bits,,0;
  * End of wire: `0` + RunBits

## 3. WL File Format (Wirelister Output)

Provides flattened, human- and tool-readable connectivity and component placement.
* **LOC Section**: Displays columns for `LOC`, `DIPTYPE`, `BODY`, `FILE`, `POS`.
* **SIGNAL Section**: Identified by `%LOC(PIN)` or `SIGNAL_NAME`, followed by pin entries.
* **Pin Entry Format**: `LOC(PIN)  TYPE  LOW  HI  USE  DIPTYPE  BODY  FILE  POS`
* **Designator Assignment Convention**: WL assigns reference designators based on the format `Xnnn`, where `X` is the body type prefix and `nnn` is `page*100 + seq`. (e.g. U100, C100)

## 4. Body Location Encoding

The physical Bay-Rack-Slot position of a body is encoded within the `card_body_loc` field (NOT to be confused with reference designators). 

From `soap.c` parser reference:
* Bits 17-15: Bay
* Bits 14-12: Rack
* Bits 11-6: Slot
* Bits 5-0: Offset

This physical coordinate allows mapping schematic placement onto backplane or chassis geography.

## 5. Data Pipeline

The typical data flow from schematic to manufacturing passes through several stages and tools:
1. **DRW** (Draw Tool): Origin format, handles visual schematics and raw graphical representation, logic diagrams.
2. **WD** (Wirelist Drawing Format): Extracted from `.drw` files, acts as an intermediate logical netlist format representing connectivity before physical wire routing.
3. **WL** (Wire Lister): A command-line tool that parses `.wd` and `.wpc` files to produce final netlists, summary files, and error checks (such as finding unnamed signals, unconnected pins, component mismatches). The WL tool assigns reference designators and resolves cross-page connections.

## 6. File Extension Reference

* **`.drw`**: Drawing File. Visual schematic information, logic or PC layout.
* **`.wd`**: Wirelist Drawing. Extracted logical netlist.
* **`.wl`**: Wire List. Human-readable and flattened list of connections.
* **`.wpc`**: PC Wirelist. Wirelist derived from printed circuit layout.
* **`.wls`**: Wire List Summary. Generated by WL.
* **`.wlu`**: Wirelist Unit summary (sorted by dip number).
* **`.prt`**: Part / Bill of Materials list. Part number and component counts.
* **`.stf`**: Stuffing file. Where DIPs are used on the board.
* **`.bom`**: Bill of Materials.
* **`.bac`**: Back panel wirelist.
* **`.plt`**: Plotter file (e.g., Calcomp).
* **`.dip`**: DIP package database (e.g., `dips.dip`).
